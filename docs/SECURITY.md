# Security model

Finder paths are attacker-influenced data (a folder can be named `$(rm -rf ~)`, contain quotes,
newlines or emoji). OpenHere is designed so such names can never be interpreted as code.

| Rule                                                                                                                                                                                                                           | Where                                 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------- |
| No shell, no `osascript`, no string-built commands. Paths travel as `URL`s or as separate `argv` entries.                                                                                                                      | `Launcher`                            |
| The only AppleScript is a constant (`FinderQuery`); nothing is interpolated.                                                                                                                                                   | `FinderQuery.swift`                   |
| `openhere://` is reachable from any web page, so requests carry a random 256-bit token generated by the app and stored in a `0600` file in the App Group container; requests without it are dropped. Constant-time comparison. | `RequestAuthenticator`                |
| App id must exist in the user's catalog; unknown ids are rejected.                                                                                                                                                             | `OpenRequestHandler`                  |
| Paths must be absolute, NUL-free, shorter than 4096 bytes and exist. Because they are always absolute they can never be parsed as command-line options (`-x`).                                                                 | `PathValidator`, `Launcher`           |
| At most 64 paths per request and 8 windows per click.                                                                                                                                                                          | `OpenHereURL`, `LaunchRequestBuilder` |
| "Copy Escaped Path" uses backslash escaping, or ANSI-C `$'…'` quoting when control characters are present.                                                                                                                     | `PathFormatter`                       |
| Custom applications: arguments are a list, never a shell string; `{path}` is required.                                                                                                                                         | `CustomApplicationFactory`            |
| Logs mark every path `.private`; the in-memory history used by diagnostics replaces paths with `<path>`, and exports contain no file paths.                                                                                    | `OpenHereLog`, `DiagnosticsExporter`  |
| Updates are downloaded from GitHub Releases and verified with an EdDSA signature (`SUPublicEDKey`) before installation.                                                                                                        | Sparkle, `UpdateService`              |

## Sandboxing analysis

- **Finder extension**: sandboxed (required). Entitlements: app sandbox + app group only. It reads
  URLs Finder hands it and opens an `openhere://` URL; it cannot launch other apps directly.
- **App**: intentionally **not** sandboxed. Launching arbitrary third-party terminals with
  arguments (`open -a … --args …`) and controlling Finder via Apple Events are not possible from a
  sandbox without temporary exceptions, and the app is distributed outside the Mac App Store.
  Hardened runtime is on; the extra entitlements are `application-groups`, `automation.apple-events`
  and `cs.disable-library-validation`. The last one lets the hardened runtime load Sparkle when the
  app is ad-hoc signed (no Developer ID); it means the app would also load a library that is signed by
  someone else, so the bundle must be kept intact (it is signed inside-out at release time).

## Permissions

- **Automation → Finder**: requested by macOS the first time the menu bar item or the keyboard
  shortcut needs the current Finder location. The toolbar / context menu do not need it because
  the extension already knows the selection. OpenHere never asks in advance.
- No Accessibility or Full Disk Access is used.
- The only network traffic is Sparkle's update check (the appcast on GitHub Pages, then the DMG on GitHub
  Releases). It can be turned off in Settings › General. There is no analytics or telemetry.
